# Стратегия защиты контактов в 3 слоя

## Актуализация v05 - 08.09.2026

Эта секция уточняет текущую реализацию. Исходная стратегия ниже сохранена как история и рекомендации для возможной серверной формы.

- Фактический кодированный email, Telegram, MAX и телефон сохранены. Alias, предложенный в разделе почтовой гигиены ниже, не считается подтверждённым текущим адресом и автоматически не применяется.
- Прямые контакты доступны без анкеты. Без JavaScript email раскрывается нативным `details` из отдельных частей, генератор скрыт и не может отправить поля через GET.
- Генератор сначала показывает редактируемый текст. Копирование и открытие канала - отдельные действия. Никакой серверной отправки, загрузки файлов и утверждения об отправленной заявке нет.
- Сохранены honeypot, 4 секунды от загрузки формы и прежний лимит до 5 подготовок в час. Старый ключ localStorage `dinarAgencyContactSubmits` содержит только временные отметки, без формы и источника. При отказе storage работает ограничение в памяти страницы; прямые контакты не блокируются. Это не серверная антибот-защита.
- У всех полей `ym-disable-keys`, у формы/превью `ym-hide-content`, у генератора `ym-disable-submit`. Подготовленный email открывается кнопкой: пользовательский текст не попадает в DOM href для автоматического отслеживания ссылки.
- Поля формы и готовый текст не сохраняются в storage и не отправляются через собственные ym/gtag события. Ошибки каждого аналитического транспорта изолированы.
- Источник между страницами запоминается в sessionStorage только после отдельного выбора посетителя. Без разрешения или при отказе хранилища используется текущая страница. Подробности и официальные источники: `docs/redesign-v05.md`.
- Существующий режим загрузки аналитики на публичном домене сохранён; local previews не загружают счётчики. Утверждённых политики/согласий/реквизитов в задаче не получено. Владелец подтверждает их до отдельной публикации; юридическая готовность не заявляется.

## 1) Текущий UI-слой

- Email не хранится в HTML в чистом виде.
- Адрес показывается только после действия пользователя (`Показать email`) и собирается в JS из частей.
- На сайте добавлена форма подготовки первого сообщения.
- Форма не отправляет данные на сервер: она собирает текст, копирует его и открывает Telegram.
- Для письма email собирается из кодированной строки только после нажатия на кнопку.
- Файл не загружается через сайт. Пользователю предлагается приложить обезличенный файл уже в Telegram или письме.

## 2) Базовый антиспам без сервера

- Honeypot-поле `company_website`.
- Time-trap через `form_started_at` (блокировка отправки быстрее 4 секунд).
- Клиентский троттлинг (не более 5 отправок за час с одного браузера).

Эти меры не заменяют серверную защиту, но текущая форма не принимает и не хранит данные на сервере.

## 3) Если позже появится серверная отправка

Endpoint `/api/contact` должен:

1. Повторно проверять honeypot (`company_website` должен быть пустым).
2. Проверять time-trap (`now - form_started_at >= 4000`).
3. Валидировать антибот-токен, если будет подключён Cloudflare Turnstile.
4. Применять rate limit по IP и/или подсети.

Пример лимитов:

- `20` запросов / `15` минут на один IP.
- `60` запросов / `15` минут на /24 подсеть IPv4 (или /64 для IPv6).

## 4) Почтовая гигиена

- Публичный alias для сайта: `site@dinardb.ru`.
- Личный ящик не публикуется.
- В DNS домена должны быть:
  - SPF (`v=spf1 include:_spf.your-mail-provider ~all`)
  - DKIM (селектор провайдера)
  - DMARC (`v=DMARC1; p=quarantine; rua=mailto:dmarc@dinardb.ru; adkim=s; aspf=s; pct=100`)
- На почтовом шлюзе/провайдере:
  - greylisting
  - репутационные блокировки
  - фильтры по шаблонам (частые спам-маркеры)
- При росте спама: ротация alias (`site+2026q1@...`, новый публичный alias и обновление формы).

## Возможная серверная схема отправки в будущем

1. Форма отправляет POST на `/api/contact`.
2. Сервер проходит проверки антибота.
3. Сервер пересылает сообщение на внутренний адрес (непубличный mailbox).
4. Ответ клиенту: `200` JSON только после успешной отправки.
